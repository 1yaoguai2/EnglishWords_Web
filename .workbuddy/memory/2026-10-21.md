## 单词背诵静态网页（本项目首个交付）

- 基于 static-web-app 技能骨架搭建：index.html + css/style.css + js/{core,parser,app,mode-spell,mode-match,mode-type}.js
- 词库发现三级降级：manifest.json → 目录浏览扫描 → 文件夹选择（file:// 下只走手动导入）
- 词库格式：每行「单词 音标 翻译」，解析器兼容空格/Tab/括号音标/无音标，编码支持 UTF-8/GBK/UTF-16
- 三种模式：打字背诵（音标提示+判分+空格看翻译）、对象连接（方块两两绑定同色分组+逐词判错）、单词打字（逐字输入+错误统计+计时）
- 踩坑：manifest 里含 `#` 的文件名（C#单词.txt）拼 URL 会被当 fragment 截断 → core.js 增加 SW.encodePath 按段 encodeURIComponent
- 端到端实测 tools/verify_app.js（playwright + msedge）：16/16 通过，无控制台报错
- 本地服务器端口 8123（后台运行中）

## 第三轮优化（同日，单词打字模式）

- 打错不再晃动界面（移除 stage/input shake 与字符缩放动画），只靠音效 + 提示条反馈
- 错误字母改为「黄色背景块」标错（--err-bg，不改字色），仍整轮保留；注意 .tc 背景不能加 transition，否则测试取 computed style 会抓到过渡起点透明
- 位置感优化：当前字母左侧闪烁竖线光标（.tc.cur::before）、当前单词整词浅色底（.tw.active）、待空格词尾显示闪烁 ␣ 符号、提示条改为胶囊样式显示「第 N / M 个单词」并在出错时高亮警示色
- 字号可调：设置页 seg（18/22/28/34）+ HUD 里 A−/A+ 步进（FONT_STEPS），持久化 word:typeFont；字体按钮点击后必须 blur()，否则空格会再次触发按钮
- 回归测试 27/27 通过

## 第四轮优化（同日，对象连接模式）

- 分组模型从「点两块配成一组」改为「三块一组：单词 + 音标 + 翻译」：M.pending 收集选块，选满 3 块自动 commit 成组（同色 hue + 编号）
- 新增组槽 UI（#matchTray）：三个带类型标签的槽位（单词/音标/翻译），显示「本组 x/3 块」与「已组好 n/m 组」；点已占槽位可取消
- 交互：点未成组方块 = 选中；再点 = 取消；同类型已占则自动替换；点已成组方块 = 整组拆开（dissolve）
- 判错修正：结果页 chips 的类型标签原先按 blocks 打乱顺序取值会错位，改为按 TYPES 顺序 findIndex 定位（word/phon/trans）
- 只有至少一块已入组的词才标 bad，全未绑定的不标色，未绑定数单独统计
- 回归测试 36/36 通过

## 第五轮优化（同日，打字背诵）

- 空格改为两级提示：第一次按空格显示翻译（不计失败），第二次按空格显示完整单词（S.reveal=2，quiz-mask.reveal 琥珀色+虚线下划线，与答对的绿色区分）
- 看答案即 rec.failed=true + rec.revealed=true，之后即使照打正确也判为未通过（msg「拼写正确，但本题已看答案，记为未通过」）
- 看答案后空输入直接回车 = 跳过本词（skip()）
- HUD 增加「看答案 N」计数（quiz-reveal，warn 色，为 0 时隐藏）；结果页统计加「看答案」一项，错词列表加 .wl-tag 琥珀色标签
- 回归测试 40/40 通过
